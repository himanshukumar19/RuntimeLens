# EVALUATION PLAN & STATISTICAL RIGOR SPECIFICATION

## 1. Pre-Registration Protocol
Before running final evaluation on the frozen held-out test set, this protocol fixes all experimental hypotheses, primary metrics, and comparisons to prevent p-hacking. The formal, tamper-evident pre-registration is committed in `docs/PREREGISTRATION.md`.

- **Primary Metric:** Macro-averaged F1 score ($\text{Macro-F1}$) across all 5 classes (`benign`, `container_escape`, `privilege_abuse`, `cryptomining`, `unknown`).
- **Primary Hypothesis ($H_1$):** Adding per-workload behavioural baseline context to the ScaleDown typed-decision model produces a statistically significant change in Macro-F1 ($\Delta\text{Macro-F1} \neq 0$) and/or benign False Positive Rate ($\Delta\text{FPR}$) compared to the identical model without baseline context.
- **Paired Evaluation:** The primary hypothesis evaluates a **strictly paired comparison** on identical scenario runs with baseline context ON versus OFF.
- **Minimum Meaningful Effect Size Calibration:** The target minimum effect size is **to be set after a real pilot** (calibrated and finalized after analyzing variance and simulation results on the real 20–30 run pilot dataset under Remediation Plan A-006).
- **Exploratory Designation:** If the pilot power analysis indicates that the 400-run budget provides insufficient statistical power ($<0.80$) to detect the calibrated effect size, the primary claim will be **pre-designated and reported as exploratory** rather than confirmatory, with full transparency regarding wide confidence intervals.
- **Secondary Comparisons:**
  1. ScaleDown Classify-1 vs Scikit-Learn Classical Random Forest Baseline.
  2. ScaleDown Classify-1 vs Default Falco Rule-Based Engine (mapped to threat classes; custom lab rules explicitly labeled).
  3. Multi-Hypothesis Correction: Holm-Bonferroni step-down method applied across all secondary comparisons.
- **Equal Tuning Budget:** All three classifiers (Rules, Random Forest, ScaleDown) are allocated the exact same dev-set tuning budget and exposure.

## 2. Dataset Partitioning, Statistical Power & Leakage Elimination
- **Total Live Cluster Runs:** **400 independent seeded runs** (60 `container_escape`, 60 `privilege_abuse`, 60 `cryptomining`, 40 `unknown`, 180 `benign`) producing 400 incidents (1 incident per run).
- **Pilot Study:** Prior to full dataset generation, a **pilot of 20–30 runs** is conducted across all classes and paired counterfactuals. The pilot validates all 5 raw telemetry streams and provides data to estimate power and CI width. Scenario implementations and raw capture designs are frozen post-pilot.
- **Split Ratio:** ~28% Held-out Test Set (**112 runs**: 17 per attack class, 11 unknown, 50 benign), 72% Dev Set (**288 runs**).
- **Statistical Power & CI Width Estimation:**
  - Rather than assuming an a priori fixed CI width, 95% bootstrap CI width and statistical power will be estimated empirically via **simulation and cluster bootstrap resampling on the pilot dataset**.
- **Grouped Stratification:** Grouped strictly by `run_id` and scenario variant. All events/incidents from a single cluster execution remain in the same partition.
- **Unseen Variant Hold-Out:** At least one scenario variant per attack class (e.g. `SC-ESC-03`, `SC-PRV-03`) is excluded entirely from the Dev set and evaluated exclusively on the held-out test set to assess out-of-distribution generalization.
- **Integrity Lock:** The partition manifest (`datasets/splits/manifest_v1.json`) and raw event hashes are committed to Git. A CI pre-flight check asserts that `SHA256(test_split)` remains identical across runs.
- **Air-Gap:** Model prompt/criteria wording and policy thresholds are tuned strictly on the Dev set. The held-out test set is evaluated once per final configuration.

## 3. Cluster-Aware Statistical Methodology
Because telemetry events within the same scenario run exhibit strong temporal and environmental correlation, standard i.i.d. assumptions do not hold.
- **Cluster-Aware Bootstrap:** 95% Confidence Intervals are generated by resampling cluster runs (`run_id`) with replacement (1,000 iterations), computing the paired metric difference $\Delta\text{Macro-F1} = \text{Macro-F1}_{\text{baseline}} - \text{Macro-F1}_{\text{no-baseline}}$ across resampled clusters, and taking the 2.5th and 97.5th percentiles.
- **Hypothesis Testing:** Paired comparisons between models use an **incident-level paired McNemar test** (and paired Wilcoxon signed-rank test across cross-validation folds).

## 4. Comprehensive Metrics Catalog

### 4.1 Classification & Detection Quality
- **Per-Class Precision, Recall, F1 & Confusion Matrix:** Unmasks minority attack class misclassifications.
- **Benign False Positive Rate (FPR):** $\frac{\text{FP}}{\text{FP} + \text{TN}}$ evaluated on the benign run corpus, with 95% bootstrap CI.
- **Detection Delay:** Elapsed time from initial malicious indicator to emitted containment action.

### 4.2 Calibration & Uncertainty (Offline Evaluation)
- **Expected Calibration Error (ECE):** Evaluated offline over 10 confidence bins with sample counts:
  $$\text{ECE} = \sum_{b=1}^{B} \frac{|B_b|}{N} |\text{acc}(B_b) - \text{conf}(B_b)|$$
  *(Note: ECE is an offline evaluation metric requiring ground truth, excluded from live runtime Prometheus exporters).*
- **Reliability Diagrams:** Plotting observed empirical accuracy against reported confidence.
- **Brier Score:** Overall multi-class probability error: $\frac{1}{N} \sum_{i} \sum_{k} (p_{ik} - y_{ik})^2$.
- **Risk-Coverage Curves:** Accuracy plotted as a function of the percentage of events passed through the confidence gate vs routed to human review.

### 4.3 Severity & Labeling Agreement
- **Teammate Agreement Reporting:**
  - Cohen's $\kappa$ between reviewers (Altaf vs Kamal) on threat classes with analytical 95% CI.
  - Cohen's $\kappa$ between each reviewer and scenario ground truth with 95% CI.
  - Weighted Cohen's Kappa ($\kappa_w$, quadratic weights) for 5-level severity scores across reviewers and against ground truth, with 95% CI.
  - Sample size: 60–80 incidents, stratified across classes and paired scenarios. Target: $\kappa \ge 0.80$. Clarifications use dev data only; definitions remain frozen after test set generation.
- **Spearman Rank Correlation ($\rho$):** Continuous model severity outputs against ground-truth rubrics.

### 4.4 Operational & SRE Performance
- **Latency Breakdown (p50, p95, p99):** Ingestion latency, correlation window wait time, classifier response time (cache hits vs misses separated), and policy evaluation latency.
- **Cost per 1,000 Events:** Combined model API cost and local compute overhead.
- **Pre-Filter Recall:** Percentage of true attack events retained after the rule pre-filter.

### 4.5 Model Decode Run-to-Run Variance & Uncertainty
- **Run-to-Run Variance Measurement:** To account for empirical non-determinism observed in hosted decoding (where identical requests produce minor variance in continuous Score and Noul values), decode variance is measured across a 25-incident Dev subset evaluated over 3 independent passes.
- **Caching Discipline:** Inference responses are cached locally keyed by `SHA256(model_id + ":" + rubric_version + ":" + state_hash)`.
- **Integrated Bootstrap Uncertainty:** Bootstrap confidence intervals for ScaleDown macro-F1, benign FPR, and severity rank correlation will incorporate the measured decode variance into the final reported uncertainty bounds.
- **Mean Time to Recovery (MTTR):** Time required to automatically roll back a false-positive quarantine.

## 5. Systematic Ablation Suite

| Ablation ID | Description | Scientific Question Answered |
|:---|:---|:---|
| **ABL-BASE** *(Primary)* | Baseline Context ON vs OFF (Paired) | Does workload context improve Macro-F1 and reduce benign FPR? |
| **ABL-PREF** | Pre-Filter ON vs OFF | What are the latency/cost savings vs missed-event risk of rule pre-screening? |
| **ABL-DESC** | Rich Discriminating Rubrics vs Minimal Names | How much does detailed prompt criteria improve SLM decision accuracy? |
| **ABL-GATE** | Confidence Threshold Sweep (0.40 to 0.90) | What is the optimal operational trade-off between human review volume and containment precision? |
| **ABL-TELEM** | Single-Source (Falco only) vs Multi-Source | Does fusing Audit, Hubble, and Trivy signals resolve ambiguities Falco misses? |
| **ABL-QUEST** | Choice-Only vs Choice+Noul vs Full (Choice+Score+Noul) | Do auxiliary typed questions improve cross-checking and calibration? |

## 6. Adversarial Injection Test Suite
A dedicated evaluation suite (isolated from primary performance metrics) testing system resilience against adversarial prompt-injection payloads embedded in process arguments, container image names, and pod labels.
- **Metrics Reported:** Attack Success Rate (ASR) — percentage of true attack scenarios flipped to `benign` by adversarial text.
- **Comparisons:** ASR measured under 4 conditions:
  1. Sanitization OFF, Deterministic Fact Override OFF
  2. Sanitization ON, Deterministic Fact Override OFF
  3. Sanitization OFF, Deterministic Fact Override ON
  4. Sanitization ON, Deterministic Fact Override ON *(Full Defense)*

## 7. Extensions Evaluation & Scope Cut Order
- **Extension 4 (Exposure-Based Risk Score):** Evaluated separately from the classifier core, testing risk ranking accuracy.
- **Extension 5 (Human Feedback Tuning Loop):** Evaluated on the Dev split only to measure drift reduction across simulated review cycles.
- **Scope Cut Priority:** Both extensions are designated lowest priority and will be dropped first if timeline constraints demand, ensuring zero disruption to the primary research claim.

## 8. Predefined Outcome Criteria
- **Positive Outcome:** The 95% paired bootstrap CI for $\Delta\text{Macro-F1}$ strictly excludes zero in the positive direction and exceeds the post-pilot calibrated minimum effect size.
- **Inconclusive Outcome:** The 95% paired bootstrap CI spans zero ($[-x, +y]$).
- **Negative Outcome:** Point estimate $\Delta\text{Macro-F1} \le 0$ or benign FPR increases.
- **Exploratory Caveat:** If the pilot study indicates insufficient power, the outcome is formally reported as exploratory findings with transparent disclosure of sample limitations.
*All outcomes are valid scientific findings and will be reported with equal rigor in the final report, poster, and viva defense.*
