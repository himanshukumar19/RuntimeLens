# RuntimeLens Verification Skill

This skill drives and verifies RuntimeLens locally. It covers telemetry ingestion webhooks, authentication enforcement, policy engine decisions, tamper-evident hash-chained audit logging, and scenario safety guardrails.

## Launch

Start an isolated RuntimeLens Falco webhook receiver on loopback with an ephemeral run ID:

```bash
RUN_ID="verify-$(date +%s)"
AUDIT_FILE="artifacts/proofs/${RUN_ID}/audit.jsonl"
PID_FILE="artifacts/proofs/${RUN_ID}/server.pid"
PORT=18765
SECRET="ephemeral-token-${RUN_ID}"

mkdir -p "artifacts/proofs/${RUN_ID}"

uv run python scripts/control_runtimelens.py start-webhook \
  --port "${PORT}" \
  --audit-file "${AUDIT_FILE}" \
  --secret "${SECRET}" \
  --pid-file "${PID_FILE}"
```

Readiness confirmation: the harness polls `http://127.0.0.1:${PORT}/falco` until the HTTP server is bound, and `control_runtimelens.py` prints JSON `{"status": "running", "pid": <pid>, ...}` to stdout.

Teardown:

```bash
uv run python scripts/control_runtimelens.py stop-webhook --pid-file "${PID_FILE}"
```

## Doctor

Run the read-only environment check before driving:

```bash
uv run python scripts/control_runtimelens.py doctor
```

The check confirms:
1. Python version is `>= 3.12`.
2. RuntimeLens core package and Pydantic models import without error.
3. Docker / OrbStack daemon is responsive.
4. Kubectl context safety guard is respected (non-lab contexts remain in safe offline mode).
5. Secret scanner verifies no leaked credentials in tracked files.

If any check fails, abort and resolve environment issues before proceeding.

## Drive

Interact with RuntimeLens using `scripts/control_runtimelens.py`:

- **Send runtime event:**
  ```bash
  uv run python scripts/control_runtimelens.py post-event \
    --port "${PORT}" \
    --secret "${SECRET}" \
    --payload '{"output": "spawned shell", "output_fields": {"k8s.ns.name": "tenant-a", "k8s.pod.name": "web-pod-1", "proc.cmdline": "sh", "time": "2026-10-23T00:00:00Z"}}'
  ```
- **Inspect response:**
  The server responds with HTTP 200 and a JSON payload containing `status`, `event_id`, policy `action`, and `record_hash`.
- **Verify audit integrity:**
  ```bash
  uv run python scripts/control_runtimelens.py verify-audit --audit-file "${AUDIT_FILE}"
  ```
- **Run scenario manifest safety linter:**
  ```bash
  uv run python scripts/control_runtimelens.py safety-lint
  ```

## Evidence

Store all verification artifacts under `artifacts/proofs/${RUN_ID}/`:

- `webhook_response.json`: raw HTTP status and response payload from the webhook receiver.
- `audit.jsonl`: persisted tamper-evident audit record generated by `AuditWriter`.
- `audit_verification.json`: output of `verify-audit` confirming cryptographic hash chaining (`valid: true`).
- `terminal_transcript.txt`: complete shell log including doctor output, start, request, and verification.

Proof standards:
1. Every run uses an isolated `RUN_ID` and a dedicated `audit.jsonl` file.
2. The audit file must verify cryptographically via SHA-256 hash chaining.
3. Teardown kills only the PID recorded in `${PID_FILE}` and leaves `artifacts/proofs/${RUN_ID}/` intact.

## Cleanup

Stop the daemon and remove ephemeral PID files while keeping proof artifacts:

```bash
if [ -f "${PID_FILE}" ]; then
  uv run python scripts/control_runtimelens.py stop-webhook --pid-file "${PID_FILE}"
fi
```

Verify that `artifacts/proofs/${RUN_ID}/audit.jsonl` and proof artifacts still exist.

## Helpers

The skill relies on `scripts/control_runtimelens.py`. Its subcommands:
- `doctor`: diagnostic environment verification.
- `start-webhook`: starts background webhook receiver on loopback.
- `stop-webhook`: gracefully stops receiver by PID.
- `post-event`: sends authenticated JSON telemetry payload over HTTP.
- `verify-audit`: checks cryptographic integrity of the audit log.
- `safety-lint`: validates scenario manifests against cluster security policies.
- `audit-dataset`: audits run directories for anti-leakage compliance.
